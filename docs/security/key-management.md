# Регламент управления ключами сообщений

## Назначение
Документ фиксирует базовый процесс управления ключами шифрования сообщений до подключения сертифицированного СКЗИ.

## Роли
- Владелец безопасности: утверждает ключевую политику и период ротации.
- Оператор платформы: внедряет ключи в защищенный контур исполнения.
- Аудитор ИБ: проверяет журнал криптоопераций и соблюдение регламента.

## Параметры среды
- `SC_MESSAGE_ENC_KEY_B64`: primary key (32 bytes в base64).
- `SC_MESSAGE_ENC_KEY_ID`: идентификатор primary key.
- `SC_MESSAGE_ENC_PREVIOUS_KEYS`: список старых ключей формата `id:keyB64,id2:keyB64`.
- `SC_MESSAGE_KEY_ROTATION_DAYS`: норматив ротации ключей.
- `SECURITY_AUDIT_SINK`: канал аудита (журнал приложения или внешний SIEM).

## Процедура ротации
1. Сгенерировать новый ключ в утвержденном контуре.
2. Назначить новому ключу новый `SC_MESSAGE_ENC_KEY_ID`.
3. Старый primary key переместить в `SC_MESSAGE_ENC_PREVIOUS_KEYS`.
4. Выполнить деплой backend.
5. Проверить, что новые сообщения шифруются новым keyId, а старые успешно расшифровываются.
6. После установленного периода ретенции вывести старый ключ из обращения.

## Ограничения
- Для production использование переменных окружения как постоянного хранилища ключей запрещается политикой ИБ.
- Перед аттестацией ключевой материал переносится в сертифицированное СКЗИ/контур управления ключами.
