# Модель угроз (черновик под аттестацию)

## Контекст
- Система: `super_chat`.
- Критичный актив: содержимое сообщений, метаданные доступа, ключевой материал.
- Цель защиты: конфиденциальность и целостность сообщений при передаче и хранении.

## Границы доверия
- Клиентское приложение (браузер) в недоверенной среде.
- Backend API/WebSocket как доверенный контур обработки.
- СУБД как среда хранения ciphertext, но без хранения plaintext.
- Внешние каналы: только TLS/WSS.

## Основные угрозы
- Перехват трафика между клиентом и сервером.
- Несанкционированный доступ к БД и чтение plaintext сообщений.
- Компрометация ключей шифрования на сервере.
- Повышение привилегий операторов/администраторов.
- Изменение зашифрованных сообщений в БД.

## Принятые контрмеры
- Принудительный TLS для backend (`REQUIRE_TLS=true`).
- Шифрование сообщений при записи в БД через криптопровайдер.
- Контроль доступа к расшифровке только после проверки членства в чате.
- Аудит криптоопераций (успех/ошибка encrypt/decrypt).
- Подготовка ротации ключей и хранение предыдущих ключей только для расшифровки.

## Остаточные риски
- Dev-криптопровайдер не является сертифицированным СКЗИ.
- Ключи в ENV допустимы только для dev/test, для production нужен сертифицированный контур KMS/СКЗИ.
